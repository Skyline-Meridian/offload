# 03. Organisation Implementation

How to build `docs/architectural design/03. organizations.md` for `docs/requirements/03. organizations.md`. Read `01. general_implementation.md` first.

## 1. Schema

Add the models from design section 2 with the standard columns: `Organisation`, `OrganisationMember`, `Coach`, `Season`, `TrainingSession`, `League`, `OrganisationLeague`, `Industry`, `ClubPathway`, `OrganisationChangeRequest`, `OrganisationSlugRedirect` (`oldSlug @unique`, `organisationId`). `OrganisationType` is `CLUB | UNION | INSTITUTION | BRAND`.

Raw SQL:

```sql
-- one current membership per manager (GEN-1.3)
CREATE UNIQUE INDEX member_one_current ON "OrganisationMember" ("userId")
  WHERE status IN ('PENDING', 'ACTIVE');
-- institution kind only for colleges/universities
ALTER TABLE "Organisation" ADD CONSTRAINT org_institution_kind CHECK
  (("type" = 'INSTITUTION') = ("institutionKind" IS NOT NULL));
ALTER TABLE "ClubPathway" ADD CONSTRAINT pathway_one CHECK
  (("institutionId" IS NULL) <> ("institutionText" IS NULL));
CREATE INDEX org_name_trgm ON "Organisation" USING gin ((immutable_unaccent(lower(name))) gin_trgm_ops);
CREATE INDEX org_type_status_name ON "Organisation" (type, status, name);
CREATE INDEX org_type_status_country ON "Organisation" (type, status, country);
```

## 4. Validation by type

One discriminated union on `type`, built from shared parts so a rule is written once:

| Part | Fields | Used by |
|---|---|---|
| `baseFields` | name (1–120), logo file id, official email, official phone (E.164), address fields, description, founded year (1800 – current year), social links, document | all |
| `sportsFields` | registration number (required, ≤ 50), training ground, playing ground (address + place id each), previous results (≤ 2,000), seasons, training sessions, coaches | CLUB, UNION, INSTITUTION |
| `leagueFields` | league ids, level (≤ 60) | CLUB, UNION |
| club only | pathways | CLUB |
| institution only | `institutionKind` required | INSTITUTION |
| brand only | website required, industry id required, `industryOther` required when industry is `other` (≤ 60) | BRAND |

- A field that does not belong to the type fails validation ("This field does not apply to brands").
- Child entries: coach (name, job role and start date required; end ≥ start), season (label, start, end required; end > start), training session (day, start and end time `HH:mm`; end > start).
- Emails: zod `email()`; URLs: `https` URLs only; social links use `normaliseSocial` from `02`.
- Labels per type ("Union registration number", "Headquarters address", "Joining date") come from one function `fieldLabel(type, field)`.

## 5. Description editor

- `RichTextEditor` uses Tiptap `StarterKit` (with headings, code, blockquote and horizontal rule turned off) plus `Link` (`openOnClick: false`, `autolink: true`, protocols `https` and `mailto`).
- The form posts the editor's HTML. The service cleans it with `sanitize-html`: allowed tags `p, br, strong, em, ul, ol, li, a`; allowed attribute `href` on `a` (schemes `https`, `mailto`); every link gets `rel="nofollow noopener noreferrer"` and `target="_blank"`.
- The visible length (text without tags) must be ≤ 5,000 characters.
- The page renders the stored, already-clean HTML with `dangerouslySetInnerHTML`. This is the only place it is allowed; a lint rule comment explains why.

## 6. Address field

`<AddressField name="address" mode="full" | "single">` used for the organisation address (`full`), training and playing grounds and offer location (`single`).

1. Loads the Maps JavaScript API with `@googlemaps/js-api-loader` (`libraries: ['places']`, key `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`, `region: 'GB'`, `language: 'en-GB'`) when the field is first focused.
2. Uses the Places Autocomplete widget (the current recommended one in Google's docs, `PlaceAutocompleteElement` at the time of writing) with a session token.
3. On selection, fetches `formattedAddress`, `addressComponents` and `id` for that place, and fills:
   - `single`: the one-line text and the hidden `placeId`
   - `full`: also line 1, line 2, city, region, postcode and country (ISO code)
4. Typing in the text after a selection clears the hidden `placeId`, and the field shows "Pick an address from the list to show it on the map".
5. On save, the service calls `checkPlaceId(placeId)` for each new or changed place id: a Place Details request with field mask `id` and `GOOGLE_PLACES_SERVER_KEY`. A 404 or invalid id returns the field error "We couldn't find this place. Pick it again from the list." Network errors after 2 retries save the address with `placeId = null` and log a warning.

`<MapEmbed placeId>` is in `01` section 14.

## 7. Registration, adding and claiming

### 7.1 Manager registration

The register Server Action (`01` section 8) for role `MANAGER` takes either a new organisation (type, name, country, address, official email and phone, plus type-required fields) or an existing organisation id. After the user is created, in one transaction:
- **New:** `uniqueSlug`, insert `Organisation` (`PENDING`), `OrganisationMember` (`PENDING`, source `NEW_ORGANISATION`), `VerificationRequest(ORGANISATION)`, notify staff.
- **Claim:** insert `OrganisationMember` (`PENDING`, source `CLAIM`) for a `PUBLISHED` organisation; notify staff.

The manager's own identity `VerificationRequest(MANAGER)` is created when they upload their document (same as players, `02` section 5.4), linked to the membership.

A manager with no current membership (left, removed, or claim rejected) sees "Add organisation" and "Claim an existing organisation" in the dashboard, which run the same services.

### 7.2 Duplicate check

`findPossibleDuplicates(tx, { type, name, country, registrationNumber })`:

```sql
SELECT id, name, city FROM "Organisation"
WHERE type = $type AND status <> 'DRAFT' AND "deletedAt" IS NULL AND (
  (country = $country AND similarity(immutable_unaccent(lower(name)), immutable_unaccent(lower($name))) > 0.6)
  OR upper(replace("registrationNumber", ' ', '')) = upper(replace($reg, ' ', ''))
) LIMIT 5
```

- The add form calls it (Server Action) when the name field loses focus and shows "Is this your organisation?" with "Claim this organisation instead". The manager can continue.
- On save, the first match is stored in `VerificationRequest.possibleDuplicateOfId`.
- The threshold `0.6` is a constant in `src/lib/constants.ts`, tuned during the migration rehearsal.

### 7.3 Slugs

`slugify`: lower case, accents removed, anything not `a-z0-9` becomes `-`, repeated `-` collapsed, trimmed, at most 80 characters. `uniqueSlug(tx, type, name)` tries `slug`, then `slug-2`, `slug-3`, … within the same type. Renaming (after the change is approved) creates a new slug and stores the old one in `OrganisationSlugRedirect`.

## 8. Editing

Route `src/app/(platform)/dashboard/organisation/page.tsx`. Sections: details, contact and address, type details, coaches, seasons, training days, leagues (clubs, unions), pathways (clubs), social, documents.

- `canEditOrganisation(viewer, org)` as in design section 4. Staff edit through the staff pages (`05`).
- **Published organisations:** a save that changes `name`, `country`, `registrationNumber` or `documentFileId` writes those values into a new `OrganisationChangeRequest` (superseding an older pending one) and saves the other fields at once. The response says "Saved. Changes to name, country, registration number or document will show after Offload approves them."
- **Pending/rejected organisations:** everything saves at once.
- After every save: `updateTag('org:' + id)`.
- "Send for review again" (rejected only): sets `PENDING`, creates a new `VerificationRequest(ORGANISATION)`, notifies staff.
- The page shows the status, its reason, "Changes awaiting review" with the new values, and the other managers' names.

## 9. Managers

- `managersToNotify(tx, orgId)`: user ids of `ACTIVE` memberships whose user is `ACTIVE`, email-verified and `documentStatus = VERIFIED`.
- `assertNotLastVerifiedManager(tx, orgId, leavingUserId)`: `SELECT … FOR UPDATE` on the organisation row, count the other verified active managers; throw `DomainError('LAST_MANAGER', 'An organisation needs at least one verified manager. Ask Offload to add another manager before you leave.')` when zero. Integration test: two managers leave at the same time in two connections; exactly one succeeds.
- `removeOrganisationFromProfile(userId)`: guard, set membership `REMOVED`, set the user's `documentStatus = NONE`, publish `membership.changed` (realtime), audit.

## 10. Public pages and directories

### 10.1 Routes

| Route | File |
|---|---|
| `/clubs`, `/unions`, `/colleges-universities`, `/brands` | `src/app/(platform)/<route>/page.tsx`, each rendering `<OrganisationDirectory type=…>` |
| `/clubs/[slug]` (and the other three) | `src/app/(public)/<route>/[slug]/page.tsx`, each rendering `<OrganisationPage type=… slug=…>` |

Explicit folders per type are used instead of a top-level `[type]` segment, which would catch every unknown URL.

### 10.2 Organisation page

```tsx
export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  return <OrganisationPage type="CLUB" slug={slug} />
}

async function getPublicOrganisationCached(type: OrganisationType, slug: string) {
  'use cache'
  const org = await getPublicOrganisation(type, slug)   // PUBLISHED and not deleted only
  if (org) cacheTag(`org:${org.id}`)
  cacheLife('hours')
  return org
}
```

- Unknown slug: look up `OrganisationSlugRedirect` and `permanentRedirect` to the current slug, else `notFound()`.
- Cached parts: details, coaches, seasons, training days, grounds, maps (by place id), open offers list (tag `org-offers:<id>`, refreshed when an offer changes).
- Per-viewer parts inside `<Suspense>`: the "Message" button and the players section.
- **Players section (ORG-9.4):** `canViewPlayers(viewer)` decides between the player cards, "Log in to view" and "Subscribe to view". The list is players whose `currentClubId` / `currentUnionId` / `currentInstitutionId` equals the organisation id and who are listed.
- `generateMetadata` gives title, description (first 160 characters of the description text) and the logo as the Open Graph image. `src/app/sitemap.ts` lists published organisations.

### 10.3 Directories

- Login required. Base: `type = X AND status = 'PUBLISHED' AND deletedAt IS NULL`.
- Search by name (trigram as in `02`), sort by name (A–Z) or newest.
- Filters: league and level (clubs, unions), institution kind (colleges/universities), industry (brands), country, "Has active offer" (`EXISTS (SELECT 1 FROM "Offer" o WHERE o."organisationId" = org.id AND o.status = 'PUBLISHED' AND o."expiresAt" > now())`).
- Card: logo or placeholder, name, type label ("College" or "University" for institutions), city and country.
- Infinite loading, 24 at a time.

## 11. Unpublish, republish and delete

Called by staff (`05`):
- `unpublish(orgId, reason)`: one transaction: status `UNPUBLISHED`, `statusReason`, pause the subscription (`06` service `pauseForOrganisation`), notify managers, audit. The Stripe call in the pause runs before commit; if it fails, the whole action fails.
- `republish(orgId)`: status `PUBLISHED`, resume the subscription, notify, audit.
- `deleteOrganisation(orgId)`: the guards and steps in design section 9. The name stays; `deletedAt` is set; every other public field is cleared; logo, coach images and documents are deleted from storage after commit.
