# 02. Player Implementation

How to build `docs/architectural design/02. player.md` for `docs/requirements/02. player.md`. Read `01. general_implementation.md` first; its patterns (Server Actions, gates, infinite loading, files, actor columns) are not repeated here.

---

## 1. Schema

Add to `prisma/schema.prisma` exactly as in design section 1, plus the standard columns:

- `PlayerProfile` (one per player user, `userId @unique`, `onDelete: Cascade` from `User`)
- `PlayerCountry`, `PlayerAgeGroup`, `PlayerQualification`, `PlayerSkill` (composite ids, cascade from `PlayerProfile`)
- `ClubHistory`, `Achievement`, `FeaturedVideo` (cascade from `PlayerProfile`)
- Reference tables `Position`, `Skill`, `Qualification`, `Country` (slug or code ids, `isActive`, `sortOrder`)
- On `User`: `nationalities String[] @db.Char(2)`

Raw SQL in the same migration:

```sql
-- only one of the two "current" fields may be set
ALTER TABLE "PlayerProfile" ADD CONSTRAINT player_club_one CHECK ("currentClubId" IS NULL OR "currentClubText" IS NULL);
ALTER TABLE "PlayerProfile" ADD CONSTRAINT player_union_one CHECK ("currentUnionId" IS NULL OR "currentUnionText" IS NULL);
ALTER TABLE "PlayerProfile" ADD CONSTRAINT player_institution_one CHECK ("currentInstitutionId" IS NULL OR "currentInstitutionText" IS NULL);

CREATE INDEX player_listed_idx ON "PlayerProfile" ("listedAt" DESC, id)
  WHERE "listedAt" IS NOT NULL AND "isHidden" = false;
CREATE INDEX user_nationalities_gin ON "User" USING gin (nationalities);
CREATE INDEX user_name_trgm ON "User" USING gin ((immutable_unaccent(lower("firstName" || ' ' || "lastName"))) gin_trgm_ops);
CREATE INDEX player_club_text_trgm ON "PlayerProfile" USING gin ((immutable_unaccent(lower("currentClubText"))) gin_trgm_ops);
```

`unaccent()` is not immutable, so the first migration also creates a wrapper:

```sql
CREATE FUNCTION immutable_unaccent(text) RETURNS text
  LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT
  AS $$ SELECT public.unaccent('public.unaccent', $1) $$;
```

Add B-tree indexes on `primaryPositionId`, `secondaryPositionId`, `otherPositionId`, `heightCm`, `weightKg`, `contractEndDate`, `rugbyCode` and each S&C column, and on the second column of each join table.

## 4. Policies

```ts
export function playersGate(v: Viewer | null): 'login' | 'verification' | 'subscription' | null {
  if (!v) return 'login'
  if (v.isStaff) return null
  if (v.role === 'PLAYER') return v.isVerified ? null : 'verification'
  if (v.role === 'MANAGER') return v.entitlements.subscription ? null : 'subscription'
  return 'login'
}
export const canViewPlayers = (v: Viewer | null) => playersGate(v) === null
```

- `canViewPlayerProfile(viewer, profile)`: `canViewPlayers(viewer)` and the profile is listed; or the viewer is staff; or it is the viewer's own profile.
- `canViewCv(viewer, profile)`: own profile, staff, or a manager with an active subscription. Never another player.
- Table-driven unit test: every role × verified/unverified × subscribed/unsubscribed, against the access matrix.

## 5. Profile editor

Route `src/app/(platform)/dashboard/profile/page.tsx` (player view; the manager view is in `03`). One page, one `<form>` per section, each with its own Server Action and `useActionState`. A section that saves shows "Saved" next to its button; errors show under each field.

| Section | Fields | Schema rules |
|---|---|---|
| Identity | first and last name, date of birth, nationalities, personal phone, bio, profile picture | names 1–60; date in the past; nationalities 1–5, no duplicates, codes in `Country`; phone parsed with `libphonenumber-js` to E.164; bio ≤ 2,000 |
| Playing | three positions, height, weight, current club/union/college-university, contract end date, league or union, qualifications, highest qualification, keen to relocate, retired, brand partnerships, strengths, work-ons, colour personality, soft skills, game skills | positions must be active `Position` ids; height 100–230; weight 30–200 with the message "Height must be between 100 and 230 cm" (same pattern for weight); strengths and work-ons ≤ 500 |
| Eligibility and caps | eligible countries, capped, capped countries, age groups, first cap, last cap, total caps | when capped: last cap ≥ first cap, total caps integer ≥ 0 (PLR-2.2) |
| Strength and conditioning | six tests | each optional, positive, at most 2 decimals |
| Academic | academic interests, graduated | |
| Club history | list | club name required ≤ 120; end ≥ start; coaches ≤ 300 |
| Achievements | list | title required ≤ 150; year ≤ current year |
| Videos | highlight video, featured videos list | valid YouTube or Vimeo link; "How to identify me" ≤ 150 |
| Social | Instagram, YouTube, LinkedIn, Facebook, X | handle or link (section 5.2) |
| Documents | CV, identity document | upload field; identity document hidden while verified (PLR-7.4) |

### 5.1 Form controls

- Combobox and multi-select (countries, positions, skills, clubs): `react-aria-components` `ComboBox` and a tag-group multi-select built on it, in `src/components/forms/`.
- Current club / union / college-university: a combobox that searches Published organisations of the right type (Server Action `searchOrganisationsForPicker(type, q)`, 10 results) and offers "Use '<typed text>'" as the last option. Picking an organisation sets the id and clears the text, and the other way round.
- Date fields: `DatePicker` from `react-aria-components`, shown as DD/MM/YYYY.
- Checkboxes for yes/no fields, defaulting to off.

### 5.2 Normalisers

`normaliseSocial(network, input)` trims, then:
- a handle (`@name` or `name`, letters, digits, `.`, `_`, `-`) becomes the network's profile URL, for example `https://www.instagram.com/name`
- a URL must use `https` (upgrade `http`) and its host must be in the network's allowed list (`instagram.com`, `www.instagram.com`; `youtube.com`, `www.youtube.com`, `youtu.be`; `linkedin.com`, `www.linkedin.com`; `facebook.com`, `www.facebook.com`, `fb.com`; `x.com`, `twitter.com`), else the error "Enter a <Network> handle or a <network> link"
- query strings and fragments are removed

`parseVideoUrl(input)` accepts `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`, `vimeo.com/<id>`; returns `{ provider, id, canonicalUrl }`. `embedUrl` returns `https://www.youtube-nocookie.com/embed/<id>` or `https://player.vimeo.com/video/<id>?dnt=1`.

Both have unit tests with at least: plain handle, `@handle`, full link, `http` link, wrong site, tracking parameters, empty input.

### 5.3 Lists

- Club history is always shown and stored newest first: sort by `endDate` (empty = current, first), then `startDate`, both descending. There is no manual reordering; `sortOrder` is not used for club history.
- Achievements are sorted by year descending, then title.
- Featured videos keep the order they were added (`sortOrder` = position on save).
- Each list item has Edit and Delete; Delete asks "Delete this entry?".

### 5.4 Identity document

`submitIdentityDocument(fileId)`:
1. Refuse if the email is not verified ("Verify your email first") or `documentStatus = VERIFIED` (PLR-7.4).
2. In one transaction: mark any `PENDING` `VerificationRequest` for the user `SUPERSEDED`, create a new `VerificationRequest(PLAYER)` with a `VerificationDocument` row, set `documentStatus = AWAITING_REVIEW`, notify staff (`05`).

### 5.5 Completeness

`profileCompleteness(profile)` returns a whole-number percentage: filled fields ÷ counted fields × 100. Counted fields: profile picture, bio, nationalities, three positions, height, weight, current club (id or text), contract end date, league or union, qualifications, highest qualification, strengths, work-ons, colour personality, soft skills, game skills, eligible countries, the six S&C tests, academic interests (counts as filled when answered), club history (≥ 1), achievements (≥ 1), highlight video, featured videos (≥ 1), CV, at least one social link; plus capped countries, age groups, first cap, last cap and total caps only when capped. Yes/no fields other than academic interests are not counted. Shown on `/dashboard` as a bar with "Your profile is 64% complete".

## 6. Listing and the directory

### 6.1 Listing

`listPlayer` sets `listedAt = now()` (first verification) or keeps the existing value; `unlistPlayer` sets it to null. Called from: staff approval (`05`), revocation, suspension, reactivation and `deleteAccount`.

### 6.2 Query

`searchPlayers(viewer, filters, cursor?)`:
- Base: `listedAt IS NOT NULL AND isHidden = false AND user.status = 'ACTIVE'`.
- Sort: `listedAt DESC, id DESC` (default) or `listedAt ASC, id ASC`. Keyset condition from the cursor: `(listedAt, id) < (cursorListedAt, cursorId)` for descending.
- Filters (Prisma `where` unless noted):

| Filter | Condition |
|---|---|
| Search | raw SQL: `immutable_unaccent(lower(firstName || ' ' || lastName)) % immutable_unaccent(lower($q))` or `ILIKE '%' || $q || '%'` for queries under 3 characters |
| Age from–to | `dateOfBirth` between `today − (to+1) years + 1 day` and `today − from years` |
| Height, weight, S&C | `gte` / `lte` |
| Nationality | raw SQL `"User".nationalities && $1::char(2)[]` |
| Primary position | `primaryPositionId = x` |
| Any position | `OR` over the three position columns `in [...]` |
| Contract end date | `gte` / `lte` |
| Eligible countries | `countries: { some: { kind: 'ELIGIBLE', country: { in } } }` |
| Capped | `isCapped` |
| Qualification | `qualifications: { some: { qualificationId: { in } } }` |
| League or union | `rugbyCode in […]` |
| Yes/no filters | the Boolean column `= true` (or `false` when "No" is chosen) |
| Current club | `currentClub.name` trigram match OR `currentClubText` trigram match |
| Skills, match any | `skills: { some: { skillId: { in } } }` |
| Skills, match all | raw SQL `id IN (SELECT "playerId" FROM "PlayerSkill" WHERE "skillId" = ANY($1) GROUP BY "playerId" HAVING count(DISTINCT "skillId") = $n)` |

- When raw SQL is needed, build the list of matching ids in a sub-query and pass it to Prisma as `id: { in: … }` only for small sets; otherwise write the whole query with `$queryRaw` and `Prisma.sql` fragments joined with `Prisma.join`. Never concatenate strings.
- Total count: a separate `count` with the same conditions, run with `Promise.all`.
- Page size 24, infinite loading (`01` section 16.4).
- Filters live in the URL; `parsePlayerFilters` drops invalid values silently.

### 6.3 Card and filters panel

- `PlayerCard` (PLR-9.8): photo (`/media/<id>/card` or placeholder), name, primary position, current club (linked organisation name or typed text), height, weight, eligible countries (flags or codes, at most 3 then "+n"), EQP and JIFF badges, "Contract ending soon" badge.
- `contractEndingSoon(date, today)` is true when `today <= date < today + 6 months` (UK date). One function, used by card and profile.
- Filters panel: a sidebar on desktop; on mobile a drawer opened by a "Filters" button (react-aria `Modal`), with "Apply" and "Clear filters".
- No results: "No players match your filters" and a "Clear filters" button.

## 7. Profile page

`src/app/(platform)/players/[id]/page.tsx`, rendered per request:
1. `playersGate(viewer)` → gate component; then `getPlayerProfile(viewer, id)`; `notFound()` if it returns null.
2. The DAL `select` lists public fields only. A unit test checks the select contains no `email`, `personalPhone`, `dateOfBirth` or document fields; the age is computed in the DAL and returned instead of the date.
3. Sections in this order: header (photo with "Retired" and "Contract ending soon" badges, name, primary position, nationalities, age, current club), biography, playing details, strength and conditioning, eligibility and caps (cap details only when capped), qualifications, club history, achievements, soft and game skills, colour personality, strengths and work-ons, highlight video, featured videos, CV link, social links, "Message" button.
4. Empty sections show the texts from the requirements ("No club history added", "No highlight video added", "Details not provided").
5. Videos embed with `loading="lazy"` iframes and `title` attributes.

## 8. Tasks

1. Schema, raw SQL and seeds; migration applies on an empty database.
2. Validation schemas and normalisers with unit tests.
3. Policies with the table-driven test.
4. DAL with field-projection test.
5. Editor sections and actions, one at a time, each with an integration test for save and validation errors.
6. Identity document submission.
7. Completeness function with unit tests (capped and not capped).
8. Directory: query with integration tests for each filter (including empty optional fields being excluded, PLR-9.4, and match all/any), card, filters panel, infinite loading.
9. Profile page with all gates.
10. End-to-end: a player registers, completes the profile, uploads a document, staff approve, the player appears in the directory; an unsubscribed manager sees the subscription gate; a visitor sees the login gate.
