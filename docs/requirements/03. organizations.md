# 03. Organisation Requirements

An organisation is a Club, Union, College/University or Brand. Managers register it, staff verify it, and once published it has a public page and appears in its directory. Paid features need an active subscription (see `06`).

---

## 1. Organisation types and managers

| Type | Managed by | Notes |
|---|---|---|
| Club | Manager of a club | |
| Union | Manager of a union | |
| College / University | Manager of a college or university | Has a sub-type: College or University. |
| Brand | Manager of a brand | Commercial partner or sponsor. |

There is one Manager role (`01` section 3). The type of a manager's organisation, not a separate role, decides which fields, plans and pages apply. At registration the user chooses "Registering as: Club Manager / Union Manager / College / University Manager / Brand Manager", which chooses the organisation type.

**ORG-1.1** THE System SHALL record each organisation's status: Draft, Pending, Published or Rejected.

**ORG-1.2** THE System SHALL link each manager to one organisation. The organisation's type is the manager's type.

**ORG-1.3** THE System SHALL allow an organisation to have several managers.

**ORG-1.4** WHEN something is sent to an organisation (a message, a new application, a billing email, a verification notice), THE System SHALL send the same copy to every verified manager of that organisation.

**ORG-1.5** THE System SHALL not let managers add or remove other managers, or approve themselves. A manager joins an organisation by registering (new organisation) or by choosing it at registration (claim), and staff verify the manager (`05`).

**ORG-1.6** THE System SHALL let a manager remove the organisation from their own profile, for example when they retire or move to another organisation. WHEN they do, THE System SHALL end their rights over the organisation and clear their verification.

**ORG-1.7** WHEN a manager adds a new organisation after removing the previous one, THE System SHALL require staff to verify the new organisation link and the manager's identity again. The manager uploads an identity document for the new organisation.

**ORG-1.8** EVERY organisation SHALL always have at least one verified manager. THE System SHALL not let the last verified manager remove the organisation from their profile, delete their account, or be removed or suspended by staff, until another manager of the organisation is verified.

**ORG-1.9** A club MAY list partner colleges/universities ("pathway college / university"). WHEN the college or university is on the platform, THE System SHALL link to its page. WHEN it is not, THE System SHALL accept the name as free text.

|---|---|---|---|
| Name | text | yes | yes |
| Description / about | formatted text | no | yes |
| Logo | image | yes | yes |
| Official email | email | yes | yes |
| Official phone | text, international format | yes | yes |
| Website | URL | brands only | yes |
| Address line 1, address line 2 | text | no | yes |
| City | text | no | yes |
| State / region | text | no | yes |
| Postcode | text | no | yes |
| Country | country | no | yes |

For brands the address fields are labelled "Headquarters address".

**ORG-2.1** IF an email, URL or phone number has an invalid format, THEN THE System SHALL reject it with a message.

**ORG-2.2** THE System SHALL place the organisation on a map from its one-line address. IF the address cannot be found, THEN THE System SHALL save the organisation without a map and tell the manager.

## 3. Fields by type

The fields in section 2 apply to every type. This section lists only what is added.

### 3.1 Clubs, unions and colleges/universities (shared)

| Field | Type | Required when adding |
|---|---|---|
| Registration number | text | yes |
| Training ground | text | no |
| Playing ground | text | no |
| Previous years' results | text | no |
| Season layout | list of: season label, start date, end date | no |
| Training days | list of: day (Monday to Sunday), start time, end time | no |
| Coaches | list of: name, photo, start date, end date, job role | no |

The registration number is one field. Its label is "Union registration number" for clubs and unions, and "Registration number" for colleges/universities.

**ORG-3.1** IN every list entry, THE System SHALL require: season label, start date and end date (seasons); day, start time and end time (training days); name, start date and job role (coaches). The coach end date and photo are optional. For colleges/universities the coach dates are labelled "Joining date" and "Leaving date".

**ORG-3.2** IF an end date or end time in a list entry is before its start, THEN THE System SHALL reject the entry.

### 3.2 Clubs and unions

| Field | Type | Required when adding |
|---|---|---|
| Leagues | any from the leagues list (section 5) | no |
| Level | text, for example "Elite 1" | no |

### 3.3 Club

| Field | Type | Required when adding |
|---|---|---|
| Pathway college / university | see ORG-1.9 | no |

A union has the fields in sections 2, 3.1 and 3.2 and nothing more.

### 3.4 College / University

| Field | Type | Required when adding |
|---|---|---|
| Type | College or University | yes |

### 3.5 Brand

| Field | Type | Required when adding |
|---|---|---|
| Industry | one from the industries list, or "Other" with a text | yes |

Brands have no fields from section 3.1.

**Industries list** (staff can edit it): Sportswear and apparel, Sports equipment, Nutrition and supplements, Sports technology and wearables, Health and wellbeing, Healthcare and medical, Media and broadcasting, Events and entertainment, Banking and finance, Insurance, Recruitment and careers, Education and training, Travel and hospitality, Food and drink, Automotive, Retail and e-commerce, Technology and software, Property and construction, Charity and community, Other.

**ORG-3.3** WHEN a brand chooses "Other", THE System SHALL require a text of at most 60 characters and SHALL show that text as the industry on the brand's page. In directory filters, all brands with "Other" appear under "Other".

## 4. Manager profile

| Field | Type | Required |
|---|---|---|
| First name, last name | text | yes |
| Date of birth | date | yes |
| Nationality | country | yes |
| Profile picture | image | no |
| Identity document | private file | yes, for verification |
| Bio | text, max 2,000 characters | no |
| Personal phone | text | no (private) |
| Organisation | the linked organisation | yes |

The fields are the same for every manager. The type follows from the linked organisation (ORG-1.2).

**ORG-4.1** WHEN a manager edits their profile, THE System SHALL keep their verification state, except as stated in ORG-1.6.

**ORG-4.2** IF a manager has no approved organisation link, THEN THE System SHALL prompt them to select or register one, and SHALL block every organisation action until staff approve it.

## 5. Leagues

Leagues apply to clubs and unions. Starting list: Premiership (England), Championship 1 (England), Championship 2 (England), Élite 1 (France), Élite 2 (France), Women's Premier North/South (England, university), BUCS (England, university), LIT Super Sevens Series, NC1, NC2, NC3, ACT Premier Women's Competition, New South Wales Central Coast Competition (Australia), Division 1 (Belgium), Super W, Women's Super League, National Team, No league.

**ORG-5.1** THE System SHALL keep leagues as a list with a name and an optional country, editable by staff.

**ORG-5.2** THE System SHALL let a club or a union belong to several leagues.

## 6. Adding and claiming an organisation

**ORG-6.1** WHEN a manager registers a new organisation, THE System SHALL save it as Pending, link the manager, notify staff, and show the manager "Pending verification".

**ORG-6.2** WHEN a manager selects an existing organisation, THE System SHALL record a claim, notify staff, and give the manager rights only after staff approve the claim. Existing managers do not approve claims.

**ORG-6.3** IF a new organisation has the same name and country as an existing one, or the same registration number, THEN THE System SHALL suggest claiming the existing one instead.

**ORG-6.4** WHILE an organisation is Pending or Rejected, THE System SHALL show it only to its own managers and to staff.

## 7. Editing an organisation

**ORG-7.1** WHERE the manager is verified and approved for the organisation, THE System SHALL let them edit all fields in sections 2 and 3.

**ORG-7.2** THE following fields are sensitive: name, country, registration number and organisation document. A change to a sensitive field of a Published organisation SHALL need staff approval.

**ORG-7.3** WHILE a sensitive change waits for approval, THE System SHALL keep showing the approved values on the public page, keep the organisation Published, and show its managers "Changes awaiting review" with the new values. WHEN staff approve, THE System SHALL apply the new values. WHEN staff reject, THE System SHALL discard them and send the managers the reason.

**ORG-7.4** Every other field, for example training days, season layout, playing ground, previous results, coaches, description and contact details, SHALL change at once, without review.

## 8. Organisation directories

**ORG-8.1** THE System SHALL provide a separate directory for clubs, unions, colleges/universities and brands, each listing Published organisations only. An organisation is listed whether or not it has a subscription.

**ORG-8.2** Directories SHALL require login. Visitors see "You need to be logged in".

**ORG-8.3** THE directories SHALL provide:

| Directory | Search | Filters |
|---|---|---|
| Clubs | Name | League, level, country, has active offer |
| Unions | Name | League, level, country, has active offer |
| Colleges / Universities | Name | Type, country, has active offer |
| Brands | Name | Industry, country, has active offer |

**ORG-8.4** THE directories SHALL be paged and sortable by name and by newest.

**ORG-8.5** THE "has active offer" filter SHALL show only organisations with at least one offer that is Published and not expired (`04`).

## 9. Organisation page

**ORG-9.1** THE organisation page SHALL be public and indexable by search engines.

**ORG-9.2** THE page SHALL show the fields marked "shown publicly" in sections 2 and 3, the map, the organisation's open offers with a "View all offers" link, and for clubs, unions and colleges/universities: coaches, training days and season layout. Empty sections show "No coach added", "Training days not provided" or "Season layout not provided".

**ORG-9.3** THE page SHALL show a "Message" button. Only verified signed-in users can use it. Visitors are asked to log in.

**ORG-9.4** THE page SHALL list the verified players who chose this organisation as their current club, union or college/university from the platform. Players who typed a name as free text are not listed.

**ORG-9.5** THE players list on the page SHALL follow the same access rule as the players directory (`02` PLR-9.1): players, staff and managers with an active subscription see it. Visitors see "Login to view". Signed-in managers without an active subscription see "Subscribe to view". The rest of the page stays public.

**ORG-9.6** THE page SHALL never show the organisation document or managers' personal data.

## 10. What a manager can do

| Capability | Condition |
|---|---|
| Edit the organisation and own profile | Verified and approved for the organisation |
| Send and receive messages, use the inbox | Verified |
| View applications to own offers | Verified |
| Open the players directory and player profiles | Active subscription |
| Create, edit, close and delete offers | Active subscription |
| View and manage the subscription | Approved for the organisation |

**ORG-10.1** WHILE the organisation has no active subscription, THE System SHALL keep the organisation page published and every capability not marked "Active subscription" available, and SHALL show an upgrade message on the two gated capabilities.

## 11. Verification of organisations

**ORG-11.1** WHEN staff approve an organisation, THE System SHALL publish it and notify its managers.

**ORG-11.2** WHEN staff reject an organisation, THE System SHALL set it to Rejected and send the managers the reason.

**ORG-11.3** Queues and staff actions are in `05`.

## 12. Later releases

**ORG-12.1** THE System SHALL add a Banned status. Staff ban a published organisation for misconduct. WHILE an organisation is Banned: its managers cannot sign in, the organisation and its offers are not visible, and its subscription is paused.
