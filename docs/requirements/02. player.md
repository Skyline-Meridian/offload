# 02. Player Requirements

Players are free users. They register, verify their email and identity, and then appear in the players directory, where organisations with an active subscription can find them. Registration, sign-in and the verification model are in `01`.

---

## 1. Player lifecycle

| State | Condition | Player can | In directory |
|---|---|---|---|
| Registered | Account created | Edit profile, upload identity document | No |
| Email verified | Email link used | Same | No |
| Awaiting review | Identity document uploaded | Same | No |
| Verified | Email verified and staff approved the document | Also apply to offers and send messages | Yes |
| Rejected | Staff rejected the document | Upload a new document | No |
| Revoked | Staff revoked verification | Upload a new document | No |

**PLR-1.1** WHEN a player registers, THE System SHALL create the account as unverified (email and document).

**PLR-1.2** THE System SHALL list every verified player in the directory. Players cannot hide their profile in the first release.

**PLR-1.3** WHILE a player is not verified, THE System SHALL show what is missing: email verification, identity document, or staff review.

**PLR-1.4** WHEN staff approve or reject a player, THE System SHALL notify the player by email and in the app.

**PLR-1.5** THE System SHALL never charge players. Every player feature is free.

### 2.3 Eligibility and international caps

| Field | Type | Rule |
|---|---|---|
| Eligible countries | any countries | "What countries are you eligible to play for?" |
| Capped | yes/no | Default no. |

**PLR-2.1** WHEN a player sets "Capped" to no, THE System SHALL hide the cap details on the profile and SHALL ignore them in search.

**PLR-2.2** IF the last cap is before the first cap, or total caps is negative, THEN THE System SHALL reject the change with a message.

### 2.7 Videos and documents

| Field | Rule |
|---|---|
| Highlight video | One YouTube or Vimeo link. |
| Featured videos | A list. Each entry: YouTube link and "How to identify me" (text, for example "number 9, blue boots"). |

| Identity document | Private. Used only for verification. Visible to the player and staff only. |

**PLR-5.1** IF a video link is not a valid YouTube or Vimeo link, THEN THE System SHALL reject it.

**PLR-5.2** THE profile SHALL play videos inside the page. WHEN no highlight video exists, THE profile SHALL show "No highlight video added".

### 2.8 Social links

Instagram, YouTube, LinkedIn, Facebook, X. A player may enter a handle or a full link.

**PLR-6.1** THE System SHALL accept a handle or a link, SHALL check that a link points to the matching site, and SHALL show it as a clickable link.

## 3. Profile editing

**PLR-7.1** THE System SHALL provide an "Edit profile" screen with the sections in section 2.

**PLR-7.2** WHEN a player saves, THE System SHALL check every field and show errors next to the field. Valid changes SHALL appear on the profile immediately.

**PLR-7.3** THE System SHOULD show a profile completeness indicator.

**PLR-7.4** WHILE a player is verified, THE System SHALL not allow the player to upload a new identity document. WHEN staff revoke a verification (`01` GEN-5.2), THE System SHALL allow a new upload again.

## 4. Player profile page

Sections: header (photo, name, primary position, nationality, age, current club), playing details, physical testing, international eligibility and caps, qualification (EQP/JIFF), club history, soft and game skills, videos, social links, "Message" button.

**PLR-8.1** WHEN a visitor who is not signed in opens a player profile, THE System SHALL show "You need to be logged in" with a login button and no player data.

**PLR-8.2** WHEN a signed-in manager without an active subscription opens a player profile, THE System SHALL show "You need to be subscribed" with a link to the plans.

**PLR-8.3** THE System SHALL show the "Message" button only to verified users.

**PLR-8.4** THE profile SHALL never show the player's email, phone, date of birth, identity document or billing details.

## 5. Players directory

**PLR-9.1** THE System SHALL show the directory only to signed-in players, staff and managers whose organisation has an active subscription. Visitors see "You need to be logged in". Other managers see "You need to be subscribed to view and access the players database" with a link to the plans.

**PLR-9.2** THE directory SHALL list verified players, newest first by default, in pages.

**PLR-9.3** THE directory SHALL provide these filters, which can be combined:

| Filter | Type |
|---|---|
| Search | Text across name and club |
| Age (from date of birth) | Range |
| Height | Range |
| Weight | Range |
| Nationality | Several countries |
| Primary position | One position |
| Any position (primary, secondary or other) | Several positions |
| Contract end date | Date range |
| Eligible countries | Several countries |
| Capped | Yes/No |
| Qualification | EQP, JIFF |
| League or union player | League only, Union only, Both |
| Max speed, Broad jump, 1200 test, CMJ, Bench 1RM, Squat 1RM | Range each |
| Graduated | Yes/No |
| Academic interests | Yes/No |
| Interested in brand partnerships | Yes/No |
| Sort | Joined: newest first, oldest first |

**PLR-9.4** WHERE a filter is set on an optional field, THE directory SHALL exclude players who left that field empty.

**PLR-9.5** WHEN no player matches, THE directory SHALL show "No players match your filters" and a "Clear filters" action.

**PLR-9.6** THE directory SHALL also provide these filters:

| Filter | Type |
|---|---|
| Current club | Text, matching both platform clubs and typed club names |
| Retired | Yes/No |
| Keen to relocate | Yes/No |
| Soft skills | Several skills |
| Game skills | Several skills |

**PLR-9.7** THE soft skills and game skills filters SHALL each offer a "Match any / Match all" switch. "Match any" (the default) finds players with at least one selected skill. "Match all" finds players with every selected skill.

**PLR-10.1** Players SHALL not be able to hide their profile in the first release. A hide option may be added later.

**PLR-10.2** THE System SHALL let a player delete their account (see `01` GEN-9.2).

**Positions** (15): Tight Head, Hooker, Loose Head, Second Row (4), Second Row (5), Blindside Flank (6), Openside Flank (7), Back Row (8), Scrum Half, Fly Half, Inside Centre, Outside Centre, Blindside Wing (11), Openside Wing (14), Full Back.

**Capped age groups**: U16s, U18s, U20s, Senior, 7s.

**League or union player**: League only, Union only, Both.

**Countries**: the ISO 3166-1 country list (248 entries) with English names. Used for nationality, eligible countries, capped countries and organisation country.

**PLR-11.1** THE System SHALL let staff add, rename and retire entries in the positions, soft skills, game skills and qualification lists without losing existing player data.
